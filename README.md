# CQA — оценка качества диалогов (фронтенд-прототип)

Учебный прототип для хакатона Conversation Quality Analytics. Это не продукт и не сайт компании.
Чистые HTML, CSS и JavaScript (ES-модули). Без фреймворков, сборки и авторизации. Интерфейс на русском.

## Демо на Vercel

Продакшен: **https://cqa-prototype.vercel.app** (проект `cqa-prototype` в команде moggers2). Сайт работает на моках, как и локально.

Повторный деплой из папки проекта:

```bash
npx vercel@latest deploy --prod
```

Серверный прокси к API организаторов — функция [api/conversations.js](api/conversations.js): `GET /api/conversations?group_id=DEV`.

1. В настройках проекта Vercel → Environment Variables задайте `CQA_DEV_URL` — GET-ссылку организаторов для DEV. Ссылка хранится на сервере и в браузер не попадает; прокси меняет в ней только `group_id`, проверяя формат (латиница, цифры, `-`, `_`).
2. В [js/config.js](js/config.js) поставьте `DATA_SOURCE: 'api'` и задеплойте заново.

Без `CQA_DEV_URL` прокси отвечает 503 с понятной ошибкой. Если API организаторов не ответит за 15 секунд — 504, если вернёт не JSON — 502. Эндпоинта `/api/evaluate` нет, потому что модель не подключена: в режиме `api` диалоги загрузятся, а оценка покажет экран ошибки.

Локально прокси запускается через `npx vercel@latest dev`; `npx serve` и `python -m http.server` отдают только статику. В деплой не попадают `tests/`, `docs/`, `.claude/`, `.env*` и `.vercel/` (см. `.vercelignore`).

## Скорость старта

`index.html` предзагружает все 27 ES-модулей через `<link rel="modulepreload">`: они грузятся параллельно, а не цепочкой import → import. На Vercel JS загружается за 0,45–1,3 с, таблица диалогов появляется примерно через 1,3–2,7 с (разброс — сеть).

## Запуск

Нужен статический сервер: ES-модули и `fetch` моков не работают через `file://`.

```bash
npx serve .
```

Без Node подойдёт Python:

```bash
python -m http.server 5178
```

Тесты (Node 18+, без зависимостей): расчёт, «Почему такой итог», экспорт и целостность моков.

```bash
npm test
```

## Экраны и навигация

Пять разделов — одинаково в шапке и в нижней панели на телефоне: **Диалоги, Оценка, Апелляции, Чек-лист, Настройки**. В шапке справа — переключатель темы (солнце ↔ луна).

**Шапка свёрнута, пока не нажат кубик.** При открытии страницы в шапке виден только кубик в левом верхнем углу. Название, переключатель темы, панель разделов и строка контекста («DEV · 20 диалогов…») скрыты. Нажатие на кубик плавно раскрывает всё это (высота за 320 мс, элементы проявляются и съезжают на место), повторное нажатие сворачивает обратно. Сам кубик не скрывается никогда; его прежняя анимация при нажатии осталась — оборот, вспышка и искры.
- Кубик — кнопка с `aria-expanded` и подписью «Развернуть шапку» / «Свернуть шапку»; работает с клавиатуры (Enter, Space). Свёрнутые элементы не получают фокус (`inert`).
- Название рядом с кубиком — отдельная ссылка на главную: кнопку нельзя вкладывать в ссылку.
- Состояние не сохраняется: после перезагрузки шапка снова свёрнута. При переходах между разделами раскрытая шапка остаётся раскрытой.
- На телефоне (до 720 px) кубик так же раскрывает название, переключатель темы и строку контекста. Нижняя панель разделов видна всегда, иначе на телефоне не осталось бы навигации.
- При `prefers-reduced-motion` шапка раскрывается и сворачивается сразу, без анимации.

| Раздел | Маршрут | Что делает |
|---|---|---|
| Диалоги | `#/list`, `#/conversation/:id` | Сводка, поиск, фильтры по языку, каналу и статусу, экспорт набора, кнопка «Презентация 5 минут». У `p1-ru-004`, `p1-ru-007`, `p1-ru-010` и `p1-call-002` пометка «Для демо». Карточка: транскрипт с поиском и плеером слева, оценка справа |
| Оценка | `#/evaluate/:id` | Выбор диалога и чек-листа, запуск, результат с кольцом итога; в подвале — модель, провайдер и стоимость одной оценки из `config.js` |
| Апелляции | `#/appeals`, `#/review`, `#/review/:id` | Две вкладки: «Подать» (форма и список) и «Очередь проверки» (решение проверяющего). После решения — блок «было → стало»: ответ, баллы критерия и итог диалога |
| Чек-лист | `#/checklist` (`#/control` ведёт сюда же) | Редактор критериев, а в конце — шаги «Применить изменения»: сохранить новую версию и переоценить выданные диалоги с таблицей «было / стало» |
| Настройки | `#/settings` | Тема, источник данных, модель, хранилище, сброс локальных данных |

Строка контекста под шапкой: набор и число диалогов (берётся из загруженного набора), активный чек-лист с версией, источник данных — по одной подписи на значение. На телефоне она свёрнута в одну кнопку.

### Презентация 5 минут

Кнопка на странице «Диалоги» запускает пошаговую подсказку по плану защиты из задания. Каждый шаг сам открывает нужный экран (и при необходимости оценивает диалог), внизу — подпись, точки прогресса, «Назад» и «Далее»:

1. **Интерфейс и диалог (1 мин)** — карточка `p1-ru-001`, клик по доказательству.
2. **Оценка, N/A и итог (2 мин)** — `p1-ru-002`: два N/A с причиной, итог 84,62.
3. **Апелляция и решение (1 мин)** — форма с выбранным критерием 6 у `p1-ru-001`, затем «Очередь проверки».
4. **Замена критерия (1 мин)** — «Чек-лист», шаги применения в конце.

Esc или ✕ закрывают презентацию.

| Клавиша | Действие |

| `/` | Поиск: по диалогам на списке, по транскрипту в карточке |

### Сценарии показа

Для демо со снижением балла подходит `p1-ru-001`: критерий 6 «Управление диалогом» — 7 из 10 (−4,5), итог 95,5. На нём же удобно показать апелляцию (7 → 10, итог 100).

1. **Оценка чата RU.** «Оценка» → `p1-ru-001` → «Оценить». Кольцо итога заполняется до 95,5, секции 25 / 40 / 30,5.
2. **Переход к реплике.** Клик по цитате или ссылке `#5` в объяснении — реплика вспыхивает зелёным и прокручивается в центр.
3. **N/A.** `p1-ru-002`: «Выявление потребности» и «Идентификация» — N/A с причиной, вес перераспределён, итог 84,62.
4. **Грубая ошибка.** `p1-ru-004` (оскорбление) или `p1-ru-003`: красный баннер с мягко пульсирующей рамкой, итог не снижается.
5. **Звонок.** Карточка `p1-call-001` или `p1-call-002` (обрыв): ▶ у реплики переводит плеер на её время, эквалайзер двигается, текущая реплика подсвечивается.
6. **Апелляция.** «Апелляции» → «Подать» → критерий 6 у `p1-ru-001` → «Очередь проверки» → «Изменить оценку» на 10 → блок «было → стало», итог 95,5 → 100.
7. **Замена критерия.** «Чек-лист» → изменить критерий → «Сохранить и применить» → внизу «Применить к выданным диалогам».

Проверка состояний: `?cqa_mock=error` или `?cqa_mock=empty` в адресе.

## Голосовые сообщения

В `p1-ru-004` (RU) и `p1-kz-002` (KZ) клиент и оператор общаются только голосовыми сообщениями. Системные сообщения остаются текстовыми. Остальные диалоги не менялись.

> **Голос синтетический, сгенерирован для демо.**

**Данные.** У голосовой реплики, кроме `timestamp` (MM:SS, как у чатов), `speaker` и `text`, есть поля:

```json
{ "timestamp": "02:10", "speaker": "operator", "type": "voice",
  "audio_url": "/audio/p1-ru-004/7.mp3", "duration": "00:06",
  "text": "Читать договор перед подписанием не пробовали? Там всё написано, если умеете читать." }
```

`text` — полный текст сообщения и он же транскрипт; `n` в имени файла — номер реплики. `duration` взята из самого mp3, тест сверяет её с файлом. Файлы лежат в `public/audio/<id>/` и весят 12–98 КБ. Путь `/audio/…` приложение пересчитывает от своей папки (`public/audio/…`), поэтому он работает и при встраивании. На Vercel тот же адрес обслуживает правило `rewrites` в `vercel.json`.

**Как сгенерировано.**

| Диалог | Клиент | Оператор |
|---|---|---|
| p1-ru-004 | edge-tts, `ru-RU-SvetlanaNeural` | Windows System.Speech, «Microsoft Pavel» |
| p1-kz-002 | edge-tts, `kk-KZ-AigulNeural` (казахский с русскими вставками) | Windows System.Speech, «Microsoft Pavel» (по сценарию отвечает по-русски) |

Мужской голос `ru-RU-DmitryNeural` в edge-tts в день генерации отдавал звук только на фразы из одного-двух слов. Поэтому оператора (Руслан, Денис) озвучивает системный голос Windows; WAV перекодирован в mp3 48 кбит/с. В одной реплике оператора `p1-kz-002` (#3) стрелка «Пополнить → Банковская карта» заменена на «раздел „Пополнить“, затем „Банковская карта“»: синтезатор не произносит стрелку, и текст разошёлся бы со звуком.

**Интерфейс.**
- Пузырь с кнопкой ▶/⏸, волной из 36 полосок, длительностью и переключателем скорости 1× / 1,5× / 2×. Волна строится из детерминированного seed (id диалога + номер реплики), а не из аудио. Во время воспроизведения полоски окрашиваются зелёным по прогрессу, пузырь подсвечивается.
- Перемотка — клик по волне или стрелки, Home и End, когда волна в фокусе (у неё роль `slider`).
- Текст свёрнут под пузырём и раскрывается кнопкой «Показать текст». Поиск по транскрипту раскрывает текст, если нашёл в нём совпадение.
- Одновременно звучит одна запись: при старте любой другой остальные ставятся на паузу.
- Метка «голосовое» с микрофоном — в пузыре; «голосовые» — в списке диалогов; «голосовых: N» — в шапке карточки.
- Клик по `#n` в обосновании переходит к сообщению, подсвечивает его и запускает с начала. Воспроизведение запускается только по клику пользователя.
- Если файла нет, в пузыре «Аудио недоступно», кнопки выключены, текст раскрыт. Страница работает дальше.

**Оценка.** Оценщик работает по полю `text`, как и раньше; итоги не изменились (63,13 и 77,69). Интонация и тон не оцениваются, и это сказано в каждом обосновании. Для эмпатии и управления диалогом отдельно объяснено, что вывод следует из слов: грубость «если умеете читать» видна в тексте, тон для вывода не нужен.

## Модель и стоимость

Модель, провайдер и стоимость одной оценки берутся из `js/config.js` → `MODEL` и показываются на экране «Оценка» и в настройках. Пока стоимость не задана (`costPerEvaluation: null`), выводится «уточняется». Сейчас оценку дают демо-данные из `mocks/results.json` — это указано в `MODEL.provider`.

```js
MODEL: { name: 'Название модели', provider: 'Провайдер', costPerEvaluation: 0.012, currency: 'USD' }
```

## Экспорт

- **JSON:** формат результата API (`criteria`, `gross_error`, `total`), плюс финальный результат после апелляций, апелляции, чек-лист и модель. Для набора — список оценённых и неоценённых диалогов.
- **CSV:** строка на критерий. Разделитель `;`, десятичная запятая, UTF-8 с BOM — чтобы Excel с русской локалью открыл файл и казахские буквы без настроек. Ячейки, начинающиеся с `= + - @`, экранируются от выполнения формул.

## Подключение реального API

1. В `js/config.js` поставьте `DATA_SOURCE: 'api'` и вставьте ссылку организаторов вместо `{{DEV_URL}}`.
2. Браузер ходит только на свой сервер (`API_BASE`, по умолчанию `/api`). На Vercel первый эндпоинт уже есть — [api/conversations.js](api/conversations.js) (см. «Демо на Vercel»). Полный контракт сервера:
   - `GET {API_BASE}/conversations?group_id=DEV` — ответ организаторов без изменений;
   - `POST {API_BASE}/evaluate` с телом `{ conversation_id, checklist }` — результат в формате ниже.

```json
{ "conversation_id": "p1-ru-001",
  "criteria": [ { "id": 1, "answer": "yes", "points": 10, "weight": 10, "explanation": "…",
                  "evidence_ids": [5], "skipped_at": null, "na_reason": null } ],
  "gross_error": { "flag": false, "type": null },
  "total": 95.5 }
```

## Правила расчёта (`js/scoring.js`, не менялись)

- «Да» — полный вес, «Нет» — 0. Шкала: ступень / максимум × вес (критерий 6, ступень 7 → 10,5 из 15).
- N/A исключает критерий, вес применимых × 100 / сумма их весов. N/A там, где он не разрешён, считается «Нет».
- Нет применимых критериев с весом — итог «—». Итог из неокруглённых баллов, округление до 2 знаков.
- Грубая ошибка — отдельный флаг, на балл не влияет.

## Анимации

Одновременно в движении не больше двух-трёх постоянных анимаций: знак и сияние в шапке, плюс эквалайзер во время звонка или пульс рамки грубой ошибки. Остальные — однократные, на появление или действие.

- **Переходы между экранами** — View Transitions API (fade + сдвиг 10 px, 250 мс), без поддержки — CSS-появление.
- **Каскадное появление** карточек, строк и шагов с шагом 40 мс.
- **Кольцо итога** — заполнение и счётчик за 900 мс. Кольцо собрано из двух полукругов, которые поворачиваются (`rotate`), без `stroke-dashoffset`. При 100 баллах — однократный салют зелёными частицами 1,5 с (один раз на оценку).
- **Критерии.** «Да» — галочка прорисовывается слева направо за 300 мс (уезжающая шторка, `scaleX`). «Нет» — покачивание бейджа и два красных пульса. Грубая ошибка — красный баннер с мягкой пульсацией рамки.
- **Курсорная подсветка карточек** — слабый радиальный градиент следует за курсором (круг двигается `transform`-ом под содержимым). **Магнитные основные кнопки** — смещение до 4 px к курсору.
- **Звонок** — эквалайзер из 6 полосок двигается только во время воспроизведения; текущая реплика подсвечивается синхронно с аудио и подкручивается в видимую область.
- **Клик по доказательству** — реплика вспыхивает зелёным и плавно прокручивается в центр.
- **Загрузка** — шиммер-скелетоны. **Тосты** снизу — при сохранении чек-листа и подаче апелляции.
- **Шапка** — медленное «северное сияние» низкого контраста. **Переключатель темы** — солнце и луна переходят друг в друга (поворот, масштаб, прозрачность).
- **Выпадающие списки** (фильтры, выбор диалога и чек-листа, решения) — своя панель в стиле приложения: скруглённая карточка с тенью раскрывается сдвигом и масштабом, пункты появляются каскадом, при наведении подсвечиваются мятным и сдвигаются, у выбранного — зелёная галочка, стрелка поворачивается. Сделано через CSS `appearance: base-select` (Chrome и Edge 135+); в Firefox и Safari остаётся обычный системный список, функции те же.
- **Волна и свечение иконок** при нажатии, подъём карточек при наведении, счёт чисел в сводке — из прошлой версии.

Анимируются только `transform` и `opacity` (исключение — `filter: drop-shadow` для свечения иконок). При `prefers-reduced-motion` всё выключено, при скрытой вкладке — на паузе.

Из прошлой версии убраны: 3D-наклон плиток, блик на кнопках, «выпрыгивание» баллов, «дыхание» итога, пульс бейджа «Оценён» и встряска баннера — чтобы не было больше двух-трёх движений сразу.

**Производительность.** При наведении и прокрутке долгих задач главного потока нет (`longtask` = 0, `blockingDuration` кадров = 0). Слои курсорной подсветки готовятся заранее, в простое после появления карточек: вставка слоя при первом наведении заставляла перерастеризовать карточку.

## 3D-знак и иконка вкладки

- **Знак.** Изумрудный кубик на CSS 3D (`preserve-3d`, `perspective`). На передней и задней грани — «Q», у которой хвост сделан галочкой. Знак собственный и не связан с логотипами компаний. Он вращается вокруг оси Y с циклом 7 с. При наведении включается второй вращающийся слой, и скорость растёт примерно до 300°/с без скачка угла. По клику и по завершении оценки знак делает один полный оборот и вспыхивает зелёным. Размер 34 px на десктопе и 30 px на телефоне.
- **Favicon.** Тот же кубик рисуется на canvas 64×64 через аффинную проекцию граней и подставляется в `<link id="cqa-favicon">` 11 раз в секунду. Цикл оборота — 2,5 с. PNG кодируется асинхронно (`toBlob`), чтобы не блокировать главный поток: синхронный `toDataURL` давал кадры до 60 мс. Клик по странице или завершение оценки дают вспышку на 2 кадра. На скрытой вкладке, при уменьшении движения или без canvas остаётся статичный `favicon.svg`, который сгенерирован той же проекцией.

## Дизайн

- **Палитра** — изумрудная гамма. Шапка и блок итога: градиент `#06392b → #0b5e45`. Акцент `#10b981`, при наведении `#34d399`. Мятный `#d1fae5`, карточки `#f4fbf7` на фоне `#e9f4ee`. Жёлтый `#f59e0b` — только для предупреждений и апелляций, красный `#ef4444` / `#dc2626` — только для ошибок и грубых нарушений.
- **Контраст.** Изумрудный фон с белым текстом не проходит AA (2,5:1). Поэтому на изумрудных кнопках текст тёмно-зелёный `#06392b` (5,1:1), а ссылки и иконки на светлом фоне — `#047857` (5,4:1).
- **Тёмная тема:** фон `#07140f`, карточки `#0e1f18`, текст `#e6f4ec`. Переключатель в «Настройках»: «Системная» (по умолчанию), «Светлая», «Тёмная».
- **Токены.** Все цвета, отступы (кратные 4), радиусы и тени заданы переменными `--cqa-*` в `:root`. Тёмная тема переопределяет их в `.cqa-app[data-theme="dark"]`.
- Шрифт Inter (Google Fonts) с запасным системным стеком. Inter покрывает Ә Ғ Қ Ң Ө Ұ Ү Һ І — проверено по загруженным начертаниям.
- Иконки — один набор (Lucide), встроены инлайн, без загрузки скрипта.
- Доступность: видимое фокус-кольцо 2 px, `aria-label` у кнопок-иконок, подписи у полей, ошибки под полями с `aria-invalid`, модальное окно на `<dialog>`, `prefers-reduced-motion`.

## Встраивание (Dynamics 365)

Один корневой контейнер `#cqa-root`; стилей на `html` и `body` нет; все классы `cqa-*`, переменные `--cqa-*`; пути к мокам считаются от `js/config.js`; навигация через hash.

## Допущения

- **Тёмная тема ставится на `#cqa-root`, а не на `html`,** чтобы не трогать страницу-хозяина при встраивании в Dynamics 365. Системную тему отслеживает `js/theme.js` через `matchMedia('(prefers-color-scheme: dark)')` и обновляет её на лету. В CSS только один блок тёмных токенов, без дублирования.
- **Тёмно-зелёный остался только у шапки и итога.** Основные кнопки стали изумрудными с тёмным текстом.
- **Ссылки «К списку» и другие кнопки с иконками** получают волну и свечение через общий обработчик. Волна при клике по полю ввода внутри карточки не появляется.

- **Цитата #5 в p1-ru-001.** Мок был верным: оператор спрашивает и счёт, и сумму. Расхождение давало обрезание цитаты на 140 символах. Теперь цитаты показываются целиком, а все объяснения в моках сверены с репликами и ссылаются на них явно (`#5`). Тест проверяет, что каждая ссылка существует.
- **Навигация.** Пять разделов; «Подать» и «Очередь проверки» — вкладки внутри «Апелляций»; шаги «Применить изменения» — в конце «Чек-листа», старый адрес `#/control` открывает тот же экран. Карточка диалога подсвечивает «Диалоги».
- **Звонок p1-call-001, критерий 3 «Идентификация» — оставлен N/A.** Оператор подсказывает, как войти по SMS-коду (#7), но не открывает аккаунт, не раскрывает данных и не восстанавливает доступ: код клиент получает и вводит сам (#8). Защищённого действия со стороны оператора нет — по чек-листу это N/A, а не «Да» или «Нет». Если в компании консультацию по входу считают защищённым действием, правильным будет «Нет»: проверки личности в звонке не было. Причина и доказательства (#4, #7, #8) записаны в моке.
- **Суммы секций и итог после N/A** проверены тестом на всех 20 диалогах: сумма секций равна итогу, максимум секций — 100, веса применимых критериев — 100.
- **Белые края страницы.** `index.html` помечен `data-cqa-standalone`: только для такой страницы-хоста снимается отступ браузера и тема переносится на `html` (фон и полосы прокрутки). Стили компонента по-прежнему не трогают `html` и `body` при встраивании.
- **Итог показывается дважды:** компактно сверху результата (балл и флаг) и подробно внизу (прогресс, секции, «Почему такой итог»). Первое ТЗ требовало итог внизу — он там остался.
- **«Почему такой итог»** строится по правилам, а не моделью: для шкалы берётся описание ступени, для «Нет» — первое предложение объяснения.
- **Статус «Оценён»** в фильтре включает пересмотренные после апелляции диалоги.
- **Комментарий апелляции** — минимум 10 символов (было 5), чтобы проверяющий получил содержательный текст.
- **Сброс локальных данных** перенесён в «Настройки» и требует подтверждения в модальном окне.
- **Таблица** прокручивается внутри блока с закреплённой шапкой; пагинации нет — для 65 записей DEV этого достаточно.
- **p1-ru-007: N/A для консультации.** По чек-листу консультация — N/A, только если чат закончился до того, как клиент сформулировал запрос. Поэтому клиент называет лишь тему («вопрос по облигациям») и уходит, не объяснив суть. Если бы он успел задать вопрос, правильным было бы «0», а не N/A.
- **p1-ru-008: оценивается работа оператора.** Бот поздоровался и дал подсказку, но контакт, потребность и эмпатия — действия оператора, а он не подключился: «Нет». Консультация получила 5 за общую подсказку бота. Завершение — «Нет», а не N/A: чат закрыт из-за молчания оператора, возможность завершить была.
- **p1-ru-006: управление 4, а не 7.** Пауза 6 минут вдвое больше порога, и клиенту пришлось дважды напоминать о себе — это «переспрашивать», ступень 4.
- **p1-call-002: идентификация N/A.** Оператор запросил данные до раскрытия, но звонок оборвался: данные не раскрывались, защищённых действий не было. Это то же правило, что у `p1-call-001`.
- **p1-en-001 и p1-ru-002 уже соответствовали заданию.** В `p1-en-001` идентификация была «Нет» (смена e-mail без проверки), в `p1-ru-002` завершение — «Нет» (чат закрыт без прощания). Данные не менялись, теперь это закреплено тестами.
- Остальные допущения прошлой версии в силе: номера реплик с 1, `skipped_at` = `{from, to}`, время звонка = смещение от первой реплики, запись звонка — синтетический WAV с тонами, мок-оценщик ставит заглушку для новых критериев (помечена «Заглушка мока»), итог всегда пересчитывается `scoring.js`, оценки и апелляции хранятся в localStorage.

## Что не сделано

- Прокси `/api/conversations` есть, `/api/evaluate` — нет: модель не подключена.
- Реальная модель не подключена: оценку дают демо-данные; стоимость в `CONFIG.MODEL` не задана и показывается как «уточняется».
- Без сети Inter не загрузится — сработает системный шрифт (Segoe UI / Noto Sans тоже содержат казахские буквы).
- Нет редактора секций и перетаскивания критериев (порядок — кнопками ↑ ↓).
- Анимированный favicon проверен только в Chrome (headless и обычное окно). Firefox и Safari не проверялись: браузер может обновлять иконку вкладки реже или показывать первый кадр.
- Автотесты интерфейса в репозиторий не входят: проверки раздела 3 прогонялись скриптом через headless Chrome и вручную (результаты — в отчёте о сдаче).
- Голосовые сообщения сверены со звуком автоматическим распознаванием (Whisper small), а не на слух. Русские совпадают на 91–100% (расхождение — «1,5» в тексте и «полтора» в речи). Казахские распознаются хуже (30–67% по словам), хотя распознанные слова по написанию близки к тексту («Салимет сіз бе» — «Сәлеметсіз бе»); носитель языка их не проверял.
- Волна голосового — декоративная (из seed), она не отражает громкость записи.
- `index.html` не задаёт стилей `body`, поэтому остаётся стандартный отступ браузера 8 px вокруг контейнера.
